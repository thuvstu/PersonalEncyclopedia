**作成日:** 2026-08-11

**方針:** GAP-1〜6を「重大度(放置した場合の最悪の結果)」で並べ替え、実装原則§2.5(1機能1ビルド)に沿って1つずつRound化する。ライブラリ更新は機能変更と混ぜず独立させる。

## 並べ替えの根拠(重大度評価)

| GAP | 放置した場合の最悪の結果 | 重大度 |
|---|---|---|
| GAP-1 バックアップ未送信 | 端末紛失・故障・初期化で**全データ消失**(不可逆) | 🔴 最高 |
| GAP-3 APIキー平文 | 端末侵害時にキー流出、API不正利用によるコスト発生 | 🟡 中 |
| GAP-4 スレッド未対応 | まれな検索クラッシュ・不正確な結果(体験劣化、データ損失なし) | 🟡 中〜低 |
| GAP-2 exportSchema=false | それ自体は無害だが、GAP-1後のマイグレーションテストの前提になる | 🟢 低(依存関係として早めに解消) |
| GAP-5 和暦5元号のみ | 特定分野のクイズ採点が不正確(機能不全だが実害は限定的) | 🟢 低 |
| GAP-6 LocalServer単一巨大クラス | 保守性の問題のみ、ユーザー体験への直接影響なし | 🟢 低 |
| ライブラリ旧バージョン | 蓄積的な技術的負債。急ぐ理由はないが機能変更とは混ぜない | 🟢 低(独立ラウンド) |

**GAP-1(データ消失の不可逆リスク)を最優先に据え、依存関係のあるGAP-2をその直前に置く。** それ以外は実装コストの小ささ順に並べる。

## Round B — GAP-1: SAFバックアップ(最優先・最重要)

現状: 暗号化(AES-256-GCM)・30世代保持まで実装済みだが、`BackupWorker.kt`のアップロード処理が`// TODO`のまま。**今すぐ端末が壊れたら全データが消える状態**。

- [ ] **B1: SAFフォルダ選択UI** 設定画面(§11.10)に「バックアップ先フォルダを選択」ボタンを追加。`ActivityResultContracts.OpenDocumentTree()`でユーザーにフォルダを選ばせ、`ContentResolver.takePersistableUriPermission()`で永続的なアクセス権を確保し、URIを`SettingsRepository`に保存する
- [ ] **B2: SAF書き込み処理** `BackupWorker.kt`の`// TODO`部分を、`DocumentFile.fromTreeUri()`経由での暗号化ファイル書き込みに置き換える。既存の暗号化・ファイル生成ロジックは変更しない(末尾の1ステップを差し替えるだけ)
- [ ] **B3: 未設定時のフォールバック** SAFフォルダが未設定の状態でWorkManagerが動いた場合、エラーにせず「端末内のみ保存」の状態を維持し、次回起動時に設定を促す通知を出す
- [ ] **B4: バックアップ成功可視化(§6.5)** 設定画面に「最終バックアップ成功日時」を表示。24〜48時間失敗が続いたらバッジ表示
- [ ] **B5: 復元の手動テスト** 実際に空のアプリへ復元できることを一度手動で確認する(自動テストの前に、まず人間の目で確認する)
- [ ] **B6: 不要になったDrive API依存の削除判断** `play-services-auth`・`google-api-client-android`・`google-api-services-drive`・`google-http-gson`はSAF方式では不要。使っていないことを確認できたら`libs.versions.toml`から削除しAPKサイズ・攻撃面を減らす
🛑 ビルド確認 → 実機でSAFフォルダ選択→バックアップ実行→ファイルが実際に生成されることを確認 → 数日運用してB4の表示が更新され続けることを確認
