| 技術                     | 見るもの       | 役割                       |
| ---------------------- | ---------- | ------------------------ |
| **複数Embedding**        | 意味的類似性     | 模範解答との意味的近さ              |
| **Keyword / phrase**   | 明示的な語      | 必須語・専門用語の確認              |
| **Rubric分解**           | 採点項目       | 「何を満たせば何点か」を明確化          |
| **Concept extraction** | 概念         | 回答に必要な概念が存在するか           |
| **NLI**                | entailment | 学生の記述が正しい内容を含意するか        |
| **Contradiction**      | 矛盾         | 模範と逆のことを言っていないか          |
| **Cross-Encoder**      | 文同士の詳細な関係  | Embeddingより精密な比較         |
| **数値・単位検証**            | 数値・式       | LLM/Embeddingではなく決定論的に検証 |
| **構造解析**               | 因果・比較・条件など | 関係性の正しさ                  |
| **極性/否定スコープ**          | 肯定・否定      | 「A」と「Aではない」を区別           |
| **Confidence**         | 判定の確信度     | 難しい回答をLLMに回す判断           |

特に重要：否定・極性

ここは独立した評価軸にする。

例えば、

日本はプレート境界に位置する。

と

日本はプレート境界に位置しない。

はEmbeddingもキーワードも非常に似る。

したがって、

concept:
  日本
  プレート境界に位置する


polarity:
  POSITIVE / NEGATIVE

まで抽出する。

さらに、

～ない
～ではない
～わけではない
～とは限らない
～ではなく～
～以外
～できない
～する必要はない

などの否定スコープを見る。

単純な「否定語が存在するか」ではなく、

どの命題に否定が作用しているか

を見る。さらに一般化すると

   否定だけでなく、**Embeddingが苦手な「関係の反転」**を別処理にする。

   例えば、

   A → B
   B → A


   10 → 100
   100 → 10


   AよりBが大きい
   BよりAが大きい


   AがBの原因
   BがAの原因


   Aの場合
   Aでない場合

   こういうものは、文章全体の意味はかなり近いのに採点上は全く違う。

   したがって、

   Embedding = 内容が似ているか

   構造解析/NLI = その内容を正しく述べているか

   と役割分担させる。

例えば最終LLMには、

Rubric 1:
  必須概念A: 検出
  Embedding: 0.93
  Entailment: 0.96
  Contradiction: 0.02
  Polarity: 一致


Rubric 2:
  必須概念B: 検出
  Embedding: 0.89
  Entailment: 0.54
  Contradiction: 0.71
  Polarity: 逆


Rubric 3:
  数値: 20 m/s
  正解: 72 km/h
  単位変換後: 一致


総合confidence: 0.87

のような構造化された証拠を渡す。

そして、

「では何点か？」

という最終判断をLLMにさせる。

これならLLMがEmbeddingの数値だけ見て、

「まあ似てるから正解！」

となる危険をかなり減らせる。


   優先順位をつけるなら

   最初に実装する価値が高い順は、

   複数模範解答Embedding
   Rubric分解
   Keyword / phrase
   否定・極性・否定スコープ
   NLI / Contradiction
   数値・単位・式の決定論的検証
   Concept extraction
   Cross-Encoder
   Confidence / defer
   最終LLM judge
